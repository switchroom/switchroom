# Allowlist for check-vault-test-hermeticity.mjs
#
# Each path is a vault test file that REFERENCES `os.homedir()` or a
# literal `~/.switchroom` string but does NOT yet set `process.env.HOME`
# to a tmpdir. On the 2026-05-20 incident host these contaminated the
# operator's `~/.switchroom/` with fixture-named dirs (a, alice, alpha,
# b, bob, c, carol, … 22 of them survived as evidence) — the same class
# that, when it landed in `server-grants.test.ts`'s `mint_grant` path,
# rewrote the live `vault/vault.enc` to a fresh empty file and locked
# the fleet for hours.
#
# Mandate: GOAL = ZERO ENTRIES. Each entry is a tracked prod-risk on
# any shared-host install. Removing an entry means the test now sets
# `process.env.HOME = tmpDir` in its `beforeEach` (BEFORE `broker.start()`)
# and restores in `afterEach`. Follow-up tracking: file an issue when
# unsticking each entry, reference it in the PR description.
#
# DO NOT ADD NEW ENTRIES to paper over a fresh test that introduces
# the pattern — fix the test instead. The CI gate's job is to make
# adding new entries a deliberate, reviewer-visible decision.
#
# Format: one repo-relative path per line. Comments start with `#`.
# Blank lines ignored.
